# Drum Keys / Drum Pads

Two static web apps that play the archive.org
[drum-machines-collection](https://archive.org/details/drum-machines-collection)
(470 machines, ~4 GB of zips) without downloading it:

- `index.html` — **Drum Keys**, desktop: QWERTY pads over all 470 machines.
- `app/` — **Drum Pads**, mobile PWA: 4×4 pads over 16 curated famous machines, offline.

No framework, no build, no dependencies. Serve the folder (`python3 -m http.server 8000`,
or the `drum` entry in `.claude/launch.json`); `fetch` and ES modules need http.

## How samples are reached
- archive.org serves a single file out of a zip, with CORS:
  `https://archive.org/download/drum-machines-collection/<Kit>.zip/<path inside zip>` —
  build it with `sampleUrl(zip, path)` in `engine.js` (path is URL-encoded whole, `/` → `%2F`).
- The zip *listing* pages are HTML without CORS, so `kits.json` is a prebuilt index
  (`node scripts/build-index.mjs`, ~2 min). Each kit: `{name, zip, root, files, cats}`;
  `cats` is one category char per file (k s c r h o t y p), from filename regexes in `RULES`.
- Never bulk-download or re-host the samples; the PWA's service worker only caches what's played.

## Shared engine (`engine.js`)
Both apps import it. It owns: sample loading/decoding, voices + hi-hat choke, the
sequencer clock, presets, recording, count-in, metronome, undo, favorites.
Apps supply `lanes` (ids in scheduling order), `resolve(lane) -> {url, cat} | null`,
`onChange()` and `onDraw({i, hits} | {count})`. Keep DOM out of it.

- **Timing:** a Worker ticks every 25 ms; steps are scheduled on the AudioContext clock
  120 ms ahead. Never schedule with setTimeout. A hit whose sample isn't decoded yet is skipped, not played late.
- **Recording** snaps to the step nearest to when the beat was *heard*
  (`currentTime − outputLatency − baseLatency`); `skipOnce` stops a just-played-live
  note from sounding twice.
- **Choke:** category `h` stops any `o` voice that started at or before it, so `chh`
  must come before `ohh` in every lanes list.
- Lane ids are shared by presets: `kick snare clap rim chh ohh tom1-3 cym perc1 perc2`
  (+ `kick2 snare2 cym2 perc3` in the PWA). Convention: **perc1 = shaker/tambourine,
  perc2 = cowbell**. Presets are one bar of 16ths: `x` hit, `X` accent, `g` ghost, `.` rest.
- **Favorites** = beat + app-specific sound state (`capture`/`apply`). "Is this a favorite"
  is an exact match of current state, not a tracked id.

## Desktop specifics (`index.html`)
- Keys are `KeyboardEvent.code` (layout-independent). Sequencer lanes play *keys*, not
  samples, so beats follow whatever kit is loaded.
- `autoMap` fills keys by category, own category first, then `FALLBACK`; per-kit overrides are
  stored as a diff against `autoMap`.

## PWA specifics (`app/`)
- Curation is in `app/machines.js` (pads per lane; `['file', 'label']` when the sound isn't
  what the lane says). After editing, run `node scripts/build-machines.mjs`: it fails on
  any missing file and rewrites `app/machine-files.json` (the long-press swap lists).
- CR-78, Drumulator and SP-12 only have numbered samples; those pads were chosen from
  spectrograms (`guessed: true`, shown as "pads by ear"). Prefer the user's ear over the guess.
- `app/sw.js`: archive.org = cache-first in `samples-v1` (keyed by the archive.org URL, never
  the redirect target); shell = network-first in `shell-v1`. Bump `SHELL` when `SHELL_FILES` changes.
- Icons are generated by `python3 scripts/make-icons.py` (no image libs).

## Deploy
GitHub Pages from `main` (root) at https://harmonicsystems.github.io/drum-keys/ — the
app is at `/drum-keys/app/`. Everything uses relative paths, so it works in a subfolder.
Remote uses the SSH alias: `git@github-harmonicsystems:harmonicsystems/drum-keys.git`.
Pages builds lag a minute or two and are CDN-cached: verify a deploy by diffing a
served file against the local one, not by eyeballing.

## Design
Muted warm palette with dark mode, no auto-playing audio (sound starts only on a key,
pad or Play). Keep copy plain; machine notes stick to well-known facts.
